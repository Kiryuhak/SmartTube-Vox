# Подготовка защищённого обмена Яндекс OAuth для SmartTube VOX 4

**Статус:** реализация брокера подготовлена и проверена локальными тестами. Она не развёрнута, Android-клиент к ней не подключён, автоматический вход пока не работает. До развёртывания не выдавать это за исправленный Device Flow.

## Подтверждённое ограничение

Яндекс выдаёт `device_code`, `user_code`, `expires_in=300` и `interval=5`, но для текущего `client_id` первый запрос `grant_type=device_code` без секрета отвечает `invalid_client` / `Wrong client secret`. Нельзя добавлять секрет в APK. [Документация Device Flow](https://yandex.ru/dev/id/doc/ru/codes/screen-code-oauth) описывает обмен кода на токен с учётными данными клиента. Поддержка PKCE для **Device Flow** в этой документации не описана; PKCE документирован для [Authorization Code Flow](https://yandex.ru/dev/id/doc/ru/codes/code-url).

## Почему Cloudflare Workers

Оценены два способа размещения:

| Вариант | Плюсы | Ограничения |
|---|---|---|
| [Cloudflare Workers](https://developers.cloudflare.com/workers/platform/pricing/) + SQLite Durable Object | HTTPS и [серверные secrets](https://developers.cloudflare.com/workers/configuration/secrets/), без собственного VPS; [Durable Objects доступны на Free](https://developers.cloudflare.com/durable-objects/platform/pricing/) | Нужны аккаунт, публикация и проверка доступности из целевых сетей; при превышении Free лимитов сервис перестанет обслуживать запросы |
| VPS + TLS reverse proxy | Полный контроль над размещением и маршрутом из регионов пользователей | Нужен сервер, обслуживание ОС, TLS и лимитов; сейчас сервера нет |

Cloudflare выбран для подготовленной реализации из-за отсутствия VPS. Перед подключением приложения нужно проверить доступность опубликованного URL из сетей пользователей в России. Внешний доступ и расходы не предполагаются без проверки условий выбранного аккаунта.

## Контракт

`POST /oauth/yandex/device/token` с `Content-Type: application/json`:

```json
{"device_code":"<полученный код устройства>","request_id":"<новый UUID>"}
```

Других полей нет. Ответ содержит только нормализованное `state`; при успехе — `access_token` и, если Яндекс прислал, `expires_in`. `refresh_token` не сохраняется и не возвращается. Ответы имеют `Cache-Control: no-store`. URL Яндекса, `client_id`, `client_secret` и `grant_type` задаёт сервер. Брокер не является HTTP-прокси произвольного назначения.

Состояния: `authorization_pending`, `slow_down`, `access_denied`, `expired_token`, `invalid_grant`, `invalid_client`, `unauthorized_client`, `temporary_server_error`, `network_error`, `rate_limited`, `success`. Android должен показать понятное сообщение при конфигурационной ошибке, а Standard VOX продолжать работу без входа.

## Защита от злоупотреблений

- Только один метод и endpoint; тело ограничено 1024 байтами, ответ Яндекса — 4096 байтами, сетевой timeout — 10 секунд.
- Единый SQLite Durable Object ограничивает 600 запросов в минуту для сервиса, 30 в минуту на IP и один poll в 5 секунд для каждого `device_code`. В хранилище лимитов находится SHA-256 хеш кода; исходный код там не сохраняется. Неактуальные записи удаляются.
- Клиентский APK не содержит ни OAuth secret, ни статический «ключ брокера». Клиент считается публичным и недоверенным.
- Исходный код не пишет в логи коды, токены, секреты, заголовки или тела запросов. При настройке платформы не включать журналирование тела запроса/ответа и не помещать их в аналитику.
- Брокер не хранит access/refresh tokens в базе. Access token присутствует только в памяти при обмене и в ответе по HTTPS.

## Ручные предусловия

1. В консоли Яндекс OAuth проверить тип, статус, разрешения (`login:info`), настройки redirect и требования к секрету текущего приложения. Этот доступ есть у владельца, но данные консоли в репозитории недоступны. **Не присылать `client_secret` в чат или Git.**
2. Создать аккаунт Cloudflare Workers и проверить условия Free/Paid и доступность сервиса в целевых сетях.
3. Назначить `YANDEX_CLIENT_ID` как публичную переменную окружения, а `YANDEX_CLIENT_SECRET` как Worker secret через интерфейс Cloudflare или интерактивный `wrangler secret put`, без значения в командной строке. Подключить SQLite Durable Object из `wrangler.jsonc`.
4. Развернуть Worker и проверить staging на тестовом OAuth-приложении. Проверить реальный `authorization_pending`, подтверждение кода человеком, выдачу токена, лимиты и отсутствие секретов в логах.
5. Только после этого добавить публичный HTTPS URL брокера в конфигурацию Android и переключить polling с прямого Яндекса на брокер. Проверить эмулятор, Lively, Standard и повторный запуск. Ручной ввод токена оставить.

Смена `YANDEX_CLIENT_SECRET` выполняется в окружении Worker и не требует обновления APK. После ротации нужно снова проверить обмен на тестовом коде. До получения аккаунта Cloudflare и доступа к настройкам OAuth-приложения действует **MANUAL_YANDEX_CONSOLE_STEP_REQUIRED**.

## Обновление и отзыв токенов

[Яндекс может вернуть refresh token](https://yandex.ru/dev/id/doc/ru/tokens/refresh-client). Текущий Android `VotData` хранит только access token и не реализует refresh; браузерный/ручной повторный вход остаётся способом обновления после истечения срока. Добавлять `/oauth/yandex/refresh` нужно вместе с защищённым хранением refresh token в Android и отдельным аудитом. [Отзыв токенов устройства](https://yandex.ru/dev/id/doc/ru/tokens/token-invalidate) тоже требует учётных данных клиента; текущий выход удаляет локальный токен, не выполняя серверный отзыв.

## Проверка

В каталоге сервиса: `npm test`. Тесты используют mock-ответы Яндекса и не требуют настоящих секретов. Android и релизная конфигурация этой подготовкой не изменены.
