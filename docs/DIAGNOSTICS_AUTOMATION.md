# SmartTube VOX — Автоматический триаж и мониторинг диагностики (Admin Automation)

## 1. Архитектура и принципы работы

Автоматический триаж диагностических отчётов SmartTube VOX (`AutoTriageService`) предназначен для непрерывной фоновой классификации поступающих с клиентских устройств телеметрических данных и инцидентов.

### Ключевые принципы безопасности:
1. **Детерминированность без непроверенных внешних моделей**: Вся логика базируется на строгих правилах классификации категорий, сигнатур ошибок, подсистем и стадий без зависимости от недетерминированных ответов LLM.
2. **Строгий запрет автоматического закрытия (`RESOLVED`)**: Автоматический сервис **НИКОГДА** не переводит отчёты или инциденты в статус `RESOLVED`. Закрытие инцидента и подтверждение исправления осуществляются исключительно разработчиком после выпуска фикса.
3. **Версионная осведомлённость о регрессиях**: Если инцидент был помечен как `RESOLVED` в версии `V_fixed`, но с клиента поступает новый отчёт с версией `V_client >= V_fixed`, инцидент автоматически переоткрывается со статусом `IN_PROGRESS`, фиксацией `reopened_at` и генерацией оповещения `CRITICAL_DIAGNOSTIC_DETECTED`.
4. **Защита от ложных переоткрытий (Historical Occurrences)**: Если отчёт относится к ранее закрытой проблеме, но версия клиента `V_client < V_fixed`, отчёт помечается как `KNOWN_ISSUE` с пометкой об историческом проявлении в старой версии, не нарушая статус `RESOLVED` инцидента.
5. **Идемпотентность и курсор изменений**: Обработка отчётов опирается на инкрементальный поток событий `report_changes`. Повторный запуск с одинаковым курсором не порождает повторных мутаций и записей в аудит.
6. **Режим безопасного прогона (Dry-Run)**: Поддержка ключа `--dry-run` позволяет промоделировать результаты триажа и получить планируемый список мутаций без записи изменений в базу данных.

## 2. Матрица классификации статусов

| Тип отчёта / Условие | Назначенный статус отчёта | Действие с Issue | Оповещение |
| :--- | :--- | :--- | :--- |
| **Тестовый отчёт** (`purpose=TEST` или ID `*TEST*`) | `IGNORED_TEST` | — | — |
| **Новая уникальная проблема** (сигнатуры нет в базе) | `IN_PROGRESS` | Создаётся новый Issue со статусом `NEW` | При `HIGH`/`CRITICAL` -> Critical Alert |
| **Дубликат активной проблемы** (`NEW`/`IN_PROGRESS`/`KNOWN_ISSUE`) | `KNOWN_ISSUE` | Увеличивается счётчик повторений Issue | — |
| **Историческое проявление** (Issue `RESOLVED`, версия клиента `<` `fixed_in_version`) | `KNOWN_ISSUE` | Issue остаётся `RESOLVED` | — |
| **Регрессия после фикса** (Issue `RESOLVED`, версия клиента `>=` `fixed_in_version`) | `IN_PROGRESS` | Issue переоткрывается в `IN_PROGRESS`, фиксируется `reopened_at` | Critical Alert при `HIGH`/`CRITICAL` |

## 3. Детерминированная генерация заголовков инцидентов

Для удобства навигации в админ-панели формируются детерминированные заголовки:
- `DOWNLOAD` + `PACKAGING`/`MUX` -> `"Ошибка упаковки скачанного видео"`
- `DOWNLOAD` + `RESOLVING` -> `"Ошибка разрешения потоков при скачивании"`
- `BACKGROUND` -> `"Фоновое воспроизведение останавливается"`
- `OTA` -> `"Ошибка OTA при проверке или выборе APK"`
- `OFFLINE` -> `"Ошибка локального воспроизведения скачанного медиа"`
- `PLAYER` + `BUFFERING` -> `"Зависание буферизации видеопотока"`
- `PLAYER` + `DECODER`/`PREPARE` -> `"Сбой декодера при инициализации плеера"`
- `TRANSLATION` -> `"Сбой закадрового перевода звуковой дорожки"`
- `CHANNEL_GROUPS` -> `"Ошибка управления локальными группами каналов"`
- `AUTO_SETUP` -> `"Сбой модуля автонастройки кодеков"`

## 4. Запуск и использование CLI

В пакете `services/vox-diagnostics` зарегистрированы команды:

```bash
# Безопасный прогон в режиме моделирования (Dry-Run):
npm run triage:dry-run

# Боевое применение триажа:
npm run triage

# Запуск с указанием курсора и лимита:
node scripts/run_auto_triage.mjs --cursor=150 --limit=50 --apply
```

### Параметры CLI:
- `--dry-run`: Не применять изменения в БД (по умолчанию для `run_auto_triage.mjs`).
- `--apply`: Применить мутации в БД.
- `--cursor=<N>`: Начать обработку с указанного ID курсора изменений (по умолчанию `0`).
- `--limit=<N>`: Максимальное количество записей изменений за один прогон (по умолчанию `100`).

## 5. Тестирование и гарантии качества

Тестовый набор `services/vox-diagnostics/test/auto_triage.test.mjs` проверяет:
1. Корректность версионного парсера (`dev < rc < release`).
2. Создание новых инцидентов для уникальных `HIGH`/`CRITICAL` отчётов.
3. Связывание дубликатов активных проблем в `KNOWN_ISSUE`.
4. Сохранение статуса `RESOLVED` для исторических отчётов старых версий.
5. Автоматическое обнаружение регрессий и переоткрытие инцидентов.
6. Идемпотентность повторных запусков (0 дублирующих мутаций).
7. Нулевое количество изменений БД в режиме `dryRun=true`.
8. Игнорирование тестовых отчётов (`IGNORED_TEST`).
9. Строгий запрет автоматического присвоения статуса `RESOLVED`.
