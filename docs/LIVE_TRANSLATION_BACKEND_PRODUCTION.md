# Архитектура Production-бэкенда Live Translation для SmartTube VOX

## 1. Обзор и целевой пайплайн

На основе результатов технических аудитов в Patch #3, Patch #6 и Patch #8 было строго установлено:
1. **Yandex VOT** функционирует исключительно в режиме **`VOD_ONLY`** (требует канонический URL ролика YouTube, завершенный медиафайл и не поддерживает инкрементальные стримы, сырой PCM или фрагменты живого эфира).
2. Бесплатных публичных zero-auth Speech-to-Speech API в глобальной сети не существует.
3. Единственная масштабируемая, независимая и надежная архитектура для SmartTube VOX — **собственный серверный сервис трансляции (Strategy D: VOX Server-Side Orchestration)**.

### Сквозной пайплайн потока данных (End-to-End Pipeline)

```
[ Android TV / SmartTube Client ]
      │
      ▼ (PCM audio tap: 16kHz, 16-bit LE Mono, фрагменты 1500–2000 мс)
[ Fragment Assembly & PTS Normalizer ]
      │
      ▼ (HTTP/2 или HTTP/1.1 POST /v1/live/session/{id}/segment)
[ VOX Live Gateway / Orchestrator ]
      │
      ├─► [ STT Stage: Faster-Whisper ] (Распознавание речи в текст)
      │         │
      │         ▼ (исходный текст с таймингами)
      ├─► [ MT Stage: Marian NMT / Opus-MT ] (Машинный перевод текста)
      │         │
      │         ▼ (переведённый текст на целевом языке)
      └─► [ TTS Stage: Piper TTS ] (Нейросинтез речи)
                │
                ▼ (синтезированное аудио: 16kHz/22.05kHz PCM)
[ Live Gateway Assembler / Buffer ]
      │
      ▼ (HTTP Response с метриками и задержками)
[ Android TV Client: PTS Sync Controller ]
      │
      ▼ (Вторичный аудиотрек с выравниванием по PTS и jitter buffer)
[ ExoPlayer Audio Track / AudioTrack Output ]
```

## 2. Стратегия Speech-to-Text (STT)

### Выбранный движок: Faster-Whisper
**Faster-Whisper** представляет собой переработку архитектуры OpenAI Whisper на C++ библиотеке **CTranslate2**, обеспечивающую 4-кратное ускорение и снижение потребления оперативной памяти в 2 раза по сравнению с оригинальным PyTorch-движком.

### Аппаратные профили инференса
1. **CPU Inference (x86_64 с AVX2/AVX512, напр. AMD EPYC / Intel Xeon 4–8 vCPU)**:
   - Квантование: `int8` или `int8_float16`.
   - Модель: `base` (~140 МБ) или `small` (~460 МБ).
   - Real-Time Factor (RTF): 0.20 – 0.35 (аудиосегмент длительностью 2.0 секунды обрабатывается за 400–700 мс).
   - RAM: ~1.0 – 1.5 ГБ на рабочий инстанс.
2. **GPU Inference (NVIDIA T4, L4, RTX 3060/4090)**:
   - Квантование: `float16` или `int8_float16`.
   - Модель: `small` (~460 МБ) или `medium` (~1.5 ГБ).
   - RTF: 0.04 – 0.08 (аудиосегмент 2.0 секунды обрабатывается за 80–160 мс).
   - VRAM: ~2.0 – 3.5 ГБ.

### Входной формат и потоковая обработка
- Вход: строго 16 000 Гц, 16-бит signed Little-Endian, Mono PCM (формируется на клиенте `VoxPcmAudioConverter`).
- Стриминг: входное аудио режется на перекрывающиеся фрагменты по 1500–2000 мс. Контекстное окно передаёт последние 500 мс предыдущего фрагмента для предотвращения обрыва слов на стыках.
- Язык: автоматическое определение языка на первых 2 сегментах с фиксацией `language="en"` для минимизации галлюцинаций и задержки.

## 3. Стратегия машинного перевода (Translation)

### Выбранный движок: Marian NMT (Helsinki-NLP / Opus-MT)
Для задач потокового перевода компактныйMarian NMT на базе CTranslate2 или Transformers обеспечивает непревзойденное соотношение скорости и качества без необходимости дорогостоящих LLM-запросов.

### Характеристики
- **Языковая пара по умолчанию**: `en -> ru` (`Helsinki-NLP/opus-mt-en-ru`).
- **Расширение (Multi-language roadmap)**: `de/es/fr/zh/ja/ko -> ru`.
- **Задержка инференса**: 30–80 мс на предложение (15–30 слов) на CPU!
- **Потребление памяти**: ~250–350 МБ RAM на модель одной языковой пары.
- **Размер модели**: ~150–220 МБ.
- **Лицензия**: Apache 2.0 / MIT (полная юридическая чистота).
- **Пакетная обработка (Batching)**: отдельные сессии обрабатываются последовательно; на сервере входящие очереди микро-батчируются (batch size 4–8) при пиковой нагрузке.

## 4. Стратегия Text-to-Speech (TTS)

### Выбранный движок: Piper TTS
**Piper TTS** — сверхбыстрый локальный нейронный синтезатор речи на базе VITS, работающий поверх ONNX Runtime.

### Характеристики
- **Голоса (русский язык)**:
  - `ru_RU-dmitri-medium` (мужской голос, четкая дикция, сбалансированная интонация).
  - `ru_RU-irina-medium` (женский голос, высокая разборчивость на ТВ-динамиках).
  - `ru_RU-ruslan-medium` (альтернативный тембр).
- **Формат вывода**: Raw PCM 22 050 Гц или 16 000 Гц (16-bit LE).
- **Задержка генерации (RTF)**: < 0.15 на обычном CPU! 2 секунды речи синтезируются за 180–300 мс.
- **Нагрузка на CPU**: крайне низкая за счет эффективных графов ONNX. Не требует дискретной GPU.
- **Размер модели**: ~45–60 МБ на один голос.
- **Лицензия**: MIT.

## 5. Контракт серверного API

### Эндпоинты

#### 1. Создание сессии: `POST /v1/live/session`
```json
// Request
{
  "streamId": "dQw4w9WgXcQ",
  "sourceLanguage": "auto",
  "targetLanguage": "ru",
  "sampleRate": 16000,
  "channels": 1,
  "encoding": "pcm_s16le",
  "clientVersion": "32.56-vox.8-dev"
}

// Response: 201 Created
{
  "sessionId": "live-sess-8f12a9bc",
  "status": "ACTIVE",
  "sessionToken": "stk_8f12a9bc_981247",
  "expiresAt": 1728320400000,
  "maxSegmentDurationMs": 3000,
  "preferredChunkDurationMs": 2000,
  "sampleRate": 16000,
  "channels": 1
}
```

#### 2. Загрузка сегмента: `POST /v1/live/session/{id}/segment`
Запрос передает бинарное аудио (или base64) вместе с метаданными синхронизации:
- Заголовки:
  - `X-Session-Token`: `stk_...`
  - `X-Sequence`: порядковый номер сегмента (0, 1, 2...)
  - `X-Generation`: поколение воспроизведения (инкрементируется при seek/switch)
  - `X-Start-Pts-Us`: PTS начала аудиосегмента в микросекундах
  - `X-End-Pts-Us`: PTS конца аудиосегмента в микросекундах
  - `Content-Type`: `application/json` (с base64 audio) или `application/octet-stream`
- Тело ответа (200 OK):
```json
{
  "sequence": 14,
  "generation": 1,
  "status": "READY",
  "translatedAudio": "<base64_encoded_pcm_s16le>",
  "sampleRate": 16000,
  "channels": 1,
  "encoding": "pcm_s16le",
  "startPtsUs": 28000000,
  "endPtsUs": 30000000,
  "originalText": "Welcome back to the live coverage of the event.",
  "translatedText": "Добро пожаловать снова на прямую трансляцию события.",
  "sttLatencyMs": 380,
  "translationLatencyMs": 45,
  "ttsLatencyMs": 190,
  "totalLatencyMs": 615
}
```

#### 3. Получение готового сегмента: `GET /v1/live/session/{id}/segment/{sequence}`
Используется при асинхронной очереди для повторного опроса готовности сегмента.

#### 4. Завершение сессии: `DELETE /v1/live/session/{id}`
Немедленное освобождение всех очередей, буферов и отмена запущенных задач инференса.

## 6. Конвейер стадий рабочего процесса (Worker Pipeline Stages)

Каждый аудиосегмент последовательно проходит строгие типизированные состояния:

```
[ INGESTED ] ──► Валидация заголовков, размера и формата PCM
      │
      ▼
[ STT_PENDING ] ──► Очередь на распознавание речи
      │
      ▼
[ STT_RUNNING ] ──► Faster-Whisper инференс
      │
      ▼
[ TRANSLATION_PENDING ] ──► Очередь на машинный перевод
      │
      ▼
[ TRANSLATION_RUNNING ] ──► Marian NMT инференс
      │
      ▼
[ TTS_PENDING ] ──► Очередь на синтез речи
      │
      ▼
[ TTS_RUNNING ] ──► Piper TTS инференс
      │
      ▼
[ READY ] ──► Аудио готово к выдаче клиенту
```

Терминальные состояния сбоя и отмены:
- `FAILED`: Ошибка на одной из стадий с детальным типизированным кодом.
- `CANCELLED`: Сессия завершена пользователем или произошел seek.
- `STALE`: Поколение сегмента (`generation`) устарело по отношению к текущему сессионному.

## 7. Очереди, защита от перегрузок и управление ресурсами

1. **Ограниченность очередей (Bounded Queues)**:
   - `maxConcurrentSessions`: 50 (на инстанс)
   - `maxConcurrentSegments`: 100
   - `maxSegmentsPerSession`: 8 (скользящее окно сегментов)
   - `maxQueuedDurationMs`: 16 000 мс (не более 16 секунд аудио в буфере)
   - `maxSegmentBytes`: 512 КБ (для 2 секунд 16kHz mono PCM требуется ~64 КБ)
   - При превышении лимитов возвращается **HTTP 429 Too Many Requests** с типизированной ошибкой `QUEUE_FULL` / `BACKPRESSURE`.
2. **Время жизни сессии (Session TTL)**:
   - Сессия автоматически объявляется неактивной и уничтожается через **90 секунд** отсутствия новых входящих сегментов.
   - Уничтожение сессии гарантирует освобождение всей памяти, обнуление очередей и завершение воркеров.
3. **Эфемерность данных (No Storage by Default)**:
   - Вся обработка происходит исключительно в оперативной памяти (in-memory buffers).
   - Запрещено сохранение аудиопотока и распознанных текстов на постоянные дисковые носители.
   - По завершении отправки сегмента клиенту буфер немедленно освобождается GC.

## 8. Защита от злоупотреблений и клиентская аутентификация

- **Rate Limiting**: алгоритм Token Bucket с ограничением запросов на IP-адрес и на `sessionId`.
- **Сессионные токены**: короткоживущие подписанные токены `sessionToken` со сроком действия не более времени жизни сессии.
- **Bootstrap handshake**: клиент SmartTube VOX запрашивает сессию через легкий bootstrap-эндпоинт без необходимости вшивания мастер-ключей в APK.
- **Защита от открытого проксирования**: бэкенд обрабатывает строго бинарные PCM-пакеты заданного формата и категорически не выполняет произвольные сетевые запросы (arbitrary URL fetch).

## 11. Конвейерное перекрытие (Pipelining) и сохранение порядка

Для минимизации задержек сервер поддерживает параллельное конвейерное перекрытие:
- Сегмент $N$ находится на стадии синтеза TTS.
- Сегмент $N+1$ параллельно находится на стадии машинного перевода Marian NMT.
- Сегмент $N+2$ параллельно распознается Faster-Whisper.

Клиент всегда получает сегменты строго в хронологическом порядке ($N, N+1, N+2$). Если сегмент признается испорченным или превышает таймаут, клиент получает явный статус ошибки или пропуска, предотвращая зависание проигрывателя.
