# SmartTube VOX 8 — Архитектурная матрица стратегий провайдеров перевода (Live Translation Provider Strategy)

В рамках **Patch #8** выполнен детальный аудит возможных архитектурных стратегий подключения бэкендов перевода для подсистемы **Live Translation (Translation 2.0)**.

Главный принцип разработки VOX: **не подменять реальные возможности фейковыми успехами** и не создавать иллюзию работающего потокового сервиса, если подлежащий протокол технически не поддерживает инкрементальную передачу.

---

## 2. Разбор стратегий

### Стратегия A: Существующий Yandex VOT (VOD Backend)
- **Технический вердикт**: **СТРОГО VOD_ONLY**.
- **Причина**: протокол `api.browser.yandex.ru/video-translation/translate` принимает URL видео, ищет готовый кэшированный трек либо ставит всё видео в фоновую очередь. Метод `sendPartialAudio` предназначен исключительно для чанковой загрузки файла целого видео при статусе `STATUS_AUDIO_REQUESTED`.
- **Запрет**: категорически запрещено нарезать прямой эфир на 10-секундные куски и отправлять их под видом отдельных VOD видео в Яндекс. Это вызовет лавину блокировок (HTTP 429), капчи и задержки в 30–60 секунд на каждый кусок с разрывом интонаций и контекста.

### Стратегия B: Yandex Cloud SpeechKit (STT + Translate + TTS)
- **Технический вердикт**: Технически возможен, но требует коммерческой инфраструктуры.
- **Ограничения**: встраивание сервисных ключей Yandex Cloud в клиентское ТВ-приложение недопустимо с точки зрения безопасности. Необходим выделенный промежуточный сервер-шлюз, оплачиваемый аккаунт Yandex Cloud и балансировка нагрузки при масштабировании.

### Стратегия C: Внешние Realtime API (Whisper / OpenAI / ElevenLabs)
- **Технический вердикт**: Подходит для индивидуального использования энтузиастами.
- **Ограничения**: каждый пользователь должен иметь собственный API-ключ и аккаунт с балансом. На ТВ вводить такие ключи крайне неудобно, а тарифы стриминга делают эту схему экономически неприменимой для массового бесплатного приложения.

### Стратегия D: Собственная серверная оркестрация VOX (Целевая архитектура)
- **Технический вердикт**: **ЕДИНСТВЕННЫЙ ЖИЗНЕСПОСОБНЫЙ PRODUCTION-ПУТЬ**.
- **Схема**:
  1. SmartTube VOX на ТВ захватывает 2-секундные фрагменты звука (`PCM_16BIT`, 16 кГц моно) и отправляет их в `services/vox-live-gateway`.
  2. Gateway направляет чанки в пул локальных инференс-воркеров:
     - **STT**: Faster-Whisper / Sherpa-ONNX (потоковое распознавание речи);
     - **MT**: быстрый NMT-переводчик (Marian / LLM) с сохранением контекста предыдущих 2 фраз;
     - **TTS**: легковесный нейросетевой синтезатор (Piper TTS / Vits) с генерацией PCM.
  3. Gateway синхронизирует результат с базовым PTS таймлайном и возвращает готовый аудиопоток в клиентское приложение.
  4. Клиентский `VoxLivePtsSyncController` выводит звук во вторичный `AudioTrack` с удержанием 6-секундного буфера задержки.

### Стратегия E: Test Provider (Mock / Passthrough)
- **Технический вердикт**: Необходим для стабилизации клиента, калибровки таймингов, тестирования сетевых разрывов и ресемплирования без внешних затрат.
- **Честный статус**: `LIVE_REAL_TRANSLATION: NO`.

## 3. Вывод и дальнейшие шаги
Для SmartTube VOX 8 Patch #8 зафиксировано:
1. `REAL_INCREMENTAL_PROVIDER_FOUND: NO` (публичный бесплатный инкрементальный API без ключей и оплаты в интернете отсутствует);
2. Контракт провайдера расширен и стандартизирован;

4. В качестве вектора развития утверждена **Стратегия D** (разработка собственного специализированного бэкенда распознавания, перевода и синтеза речи).
