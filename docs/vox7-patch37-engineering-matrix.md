Статическая проверка веток API 28–34:

- Собственный `VoxDownloadService` использует `startForegroundService` и канал уведомлений с проверкой API 26; тип `dataSync` включается с API 29. Для `PendingIntent` используется совместимый `FLAG_IMMUTABLE`.
- Публикация MKV использует `RELATIVE_PATH`/`IS_PENDING` только с API 29. На API 28 при отсутствии разрешения на запись выбирается каталог приложения; при выданном разрешении — публичный `Movies`.
- Разрешения на уведомления и хранилище заявлены в manifest. Фоновые загрузки обслуживаются сервисом, а не WorkManager.
- Резолвер качества и UI карточек используют доступные на API 28 механизмы Android/Leanback; новых вызовов API 29+ без проверки в изменённом коде не обнаружено.

Статический аудит не равен runtime-проверке на API 28–33. Для неё нужны соответствующие TV system images.

## Tizen Preview

WGT собирается как отдельный веб-артефакт `tizen/build/SmartTube-VOX-7.0.0.wgt`. Browser bundle, иконка и `config.xml` входят в архив. Экран Preview честно сообщает, что воспроизведение ещё не подключено. Неопределённые аппаратные возможности остаются `UNKNOWN`, а отправка диагностики требует явного действия пользователя.

Tizen Studio, TV Extension, сертификат/профиль подписи и эмулятор на рабочей машине отсутствуют. WGT не подписан, поэтому установка, запуск, DPAD на устройстве и сквозная отправка отчёта из Tizen не подтверждены. Физического Samsung TV нет. Проверены сборка WGT, модульные тесты и отображение в браузере; это не аппаратная проверка.

## Ограничения доказательства

Длительная проверка TCL проводится отдельно после основных сценариев. Скорости 1.0×–2.0× проверены тестом передачи скорости в контроллер аудио; это не физическое измерение рассинхронизации на каждой скорости. Live-перевод остаётся `VOD_ONLY` в текущем backend.
