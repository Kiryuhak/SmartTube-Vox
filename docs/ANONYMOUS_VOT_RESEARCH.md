# Исследование и POC: Анонимная сессия Yandex VOT и Lively Voice

## 1. Введение и цели исследования

В рамках проекта **SmartTube VOX** было проведено исследование возможности выполнения голосового перевода видео (Yandex Video Voiceover Translation — VOT) без привязки пользовательской учетной записи Yandex ID (OAuth), а также проверка работы режима **Lively Voice** («Живой голос») в анонимном режиме.

Основные цели:
1. Реализация чистового (clean-room) механизма создания анонимной сессии (`/session/create`) на базе технически совместимого интерфейса Яндекс Браузера (статус: UNDOCUMENTED — официального публичного документирования или разрешения third-party использования не предоставлено).
2. Проверка гипотезы о работе стандартного и живого перевода без OAuth-токена пользователя.
3. Обеспечение потокобезопасности, кэширования сессий в памяти (без сохранения на диск) и предотвращения stampede-эффекта при параллельных запросах.
4. Предоставление debug-селектора для тестирования различных режимов авторизации (`AUTO`, `ANONYMOUS`, `YANDEX_ID`) без сброса существующих авторизационных данных пользователя.

## 2. Анализ протокола и архитектура

### 2.1. Создание анонимной сессии (`POST /session/create`)

API голосового перевода Яндекс Браузера (`https://api.browser.yandex.ru`) поддерживает выпуск временного сессионного ключа (`secret_key`) без авторизации пользователя:

* **Endpoint**: `https://api.browser.yandex.ru/session/create`
* **Метод**: `POST`
* **Protobuf-запрос** (`SessionRequest`):
  * Поле 1 (`uuid`): случайный 32-символьный hex-токен клиента.
  * Поле 2 (`module`): `"video-translation"`.
* **Заголовки запроса**:
  * `Accept: application/x-protobuf`
  * `Content-Type: application/x-protobuf`
  * `User-Agent: Mozilla/5.0 ... YaBrowser/...`
  * `Vtrans-Signature`: HMAC-SHA256 подпись тела запроса с использованием **протокольной подписывающей константы** (`VotConfig.HMAC_KEY`). Это симметричный HMAC-ключ; называть его «открытым ключом» терминологически неверно — он не является частью асимметричной пары ключей.
  * `Sec-Vtrans-Token`: UUID сессии.
* **Protobuf-ответ** (`SessionResponse`):
  * Поле 1 (`secret_key`): строковый сессионный ключ.
  * Поле 2 (`expires`): время жизни сессии в секундах (обычно `3600` секунд = 1 час).

### 2.2. Авторизация запросов на перевод (`POST /video-translation/translate`)

При наличии валидной сессии запросы к эндпоинту `/video-translation/translate` подписываются с использованием полученного `secret_key`:

* `Sec-Vtrans-Sk`: значение `secret_key` из активной сессии.
* `Sec-Vtrans-Token`: UUID сессии.
* `Vtrans-Signature`: HMAC-SHA256 подпись тела запроса с использованием `secret_key`.
* Заголовок `Authorization: OAuth ...` в чисто анонимном режиме **не передается**.

### 2.3. Поле Lively Voice (Field 10)

В схеме `VideoTranslationResponse` поле номер 10 (`is_lively_voice`, тип `bool`/`varint`) возвращается бэкендом:
* `isLivelyVoice = true`: синтез выполнен нейросетевой моделью «Живой голос».
* `isLivelyVoice = false` / отсутствует: стандартный двухголосый синтез.

## 3. Архитектура решения в SmartTube VOX

В модуле `common` реализована модульная архитектура сессий:

```
                  ┌───────────────────────┐
                  │   VotSessionProvider  │ (interface)
                  └───────────▲───────────┘
                              │
          ┌───────────────────┴───────────────────┐
          │                                       │
┌──────────────────────────────┐     ┌──────────────────────────────┐
│  AnonymousVotSessionProvider │     │  YandexOAuthSessionProvider  │
└──────────────────────────────┘     └──────────────────────────────┘
```

1. **`VotSessionProvider`**: Интерфейс поставщика сессии (`getOrCreateSession()`, `refreshSession()`, `invalidateSession()`, `getTranslateHeaders()`, `hasValidSession()`).
2. **`AnonymousVotSessionProvider`**:
   * Чистовой провайдер анонимных сессий.
   * Потокобезопасное получение и создание сессии с двойной проверкой блокировки (`double-checked locking`), предотвращающей повторные одновременные сетевые запросы (stampede prevention).
   * Хранение сессии **исключительно в памяти** (volatile `mSession`), время жизни контролируется локально (`System.currentTimeMillis()`) с запасом безопасности 60 секунд.
   * Подробное структурированное логирование с тегом `ANON_VOT` (фиксация возраста сессии, статуса создания, параметров ответа).
3. **`YandexOAuthSessionProvider`**:
   * Обертка над существующей авторизацией через OAuth-токен пользователя (`VotData.getOAuthToken()`).
   * Полностью сохраняет обратную совместимость для авторизованных пользователей.
4. **`VotAuthMode`**:
   * Режимы: `AUTO` (OAuth при наличии токена, иначе анонимно), `ANONYMOUS` (принудительно анонимная сессия), `YANDEX_ID` (строго OAuth).
   * В `PlayerSettingsPresenter` и `VotData` селектор режима обернут в `if (BuildConfig.DEBUG)` и полностью исключен из релизных сборок.

## 4. Результаты тестирования и ключевые выводы

### 4.1. Юнит-тестирование JVM

Тестовый набор `AnonymousVotSessionProviderTest` покрывает:
1. `testInitialStateHasNoValidSession` — начальное состояние без сессии.
2. `testGetOrCreateSessionCreatesValidSession` — создание и декодирование валидной сессии.
3. `testSessionReuseDoesNotDuplicateNetworkRequests` — кэширование и повторное использование одного экземпляра сессии.
4. `testRefreshSessionForcesNewNetworkRequest` — принудительное обновление сессии.
5. `testInvalidateSessionClearsSession` — сброс сессии.
6. `testNetworkFailureThrowsException` — корректная обработка сетевых сбоев.
7. `testConcurrentRequestsPreventStampede` — многопоточный стресс-тест на 10 потоков без дублирования вызовов.
8. `testHeadersUseSessionWhenValid` — корректное формирование заголовков `Sec-Vtrans-Sk`, `Sec-Vtrans-Token`, `Vtrans-Signature` и отсутствие `Authorization`.

**Результат**: 8 из 8 тестов успешно пройдены (`BUILD SUCCESSFUL`).

### 4.2. Тестирование на Android TV Emulator (Vox-TV-14 / Android 14)

* **Создание сессии**: При старте первого видео выполнен запрос к `/session/create`, сессия получена за 521 мс (`expires=3600s`).
* **Повторное использование сессии**: При переключении на следующее видео в логах зафиксировано `ANON_VOT session age: 116s`. Запрос `/session/create` **не повторялся**, заголовок `Sec-Vtrans-Sk` сформирован мгновенно (ответ бэкенда за 98 мс).
* **Поведение Lively Voice в анонимном режиме**:
  * Для популярных видео, где перевод уже сгенерирован в кэше сервиса, бэкенд возвращает статус `1` (`STATUS_FINISHED`) и маркер `isLivelyVoice=true` **даже без передачи OAuth-токена пользователя**!
  * Для видео, не имеющих готового кэша Lively Voice, сервер возвращает статусную последовательность, требующую сессию или очередь. При `useLively=true` клиент корректно обрабатывает полученный поток и при необходимости переключается на стандартный голос.
* **Синхронизация и воспроизведение**:
  * Зафиксирована непрерывная синхронизация аудиопотока перевода с основным плеером: `VOT_AUDIO sync video_pos=... trans_pos=... delta=16-74ms state=ACTIVE`.
  * Даккинг оригинального звука, пауза и возобновление работают штатно.

## 5. Правовые аспекты, безопасность и конфиденциальность (ToS & Privacy)

1. **Clean-room реализация**: Все компоненты реализованы с нуля на основе наблюдаемых сетевых контрактов (network traffic observation) и открытых исходников (FOSWLY/vot.js, MIT). Декомпиляция закрытых библиотек не производилась.
2. **Конфиденциальность пользователя**: Анонимный режим полностью исключает передачу учетных данных пользователя (Yandex ID) на внешние серверы. История просмотров не связывается с персональным профилем.
3. **Безопасность хранения**: Сессионные ключи (`secret_key`) существуют только в оперативной памяти процесса приложения и сбрасываются при завершении работы или истечении TTL (1 час).
4. **Нагрузка на инфраструктуру**: Благодаря локальному кэшированию сессий и защите от параллельных запросов нагрузка на эндпоинт `/session/create` сведена к минимуму (не более одного запроса в час при непрерывном воспроизведении).

## 6. Происхождение протокольной подписывающей константы (HMAC Key Material)

**Статус**: OPEN_SOURCE_PROTOCOL

Протокольная подписывающая константа (HMAC-SHA256 key material, хранится в `VotConfig.HMAC_KEY`) идентифицирована в открытом репозитории:

| Параметр | Значение |
|---|---|
| Репозиторий | `FOSWLY/vot.js` |
| Лицензия | MIT |
| Файл | `packages/shared/src/data/config.ts`, поле `hmac` |
| URL | `https://github.com/FOSWLY/vot.js` |

Это **симметричный** HMAC-ключ, общеизвестный в open-source сообществе. Он **не является** «публичным ключом» (asymmetric public key) — данная терминология неприменима к симметричным HMAC signing constants.

## 8. Заключение

Прототип доказал полную техническую состоятельность анонимного режима Yandex VOT в SmartTube VOX. Он обеспечивает стабильное воспроизведение качественного голосового перевода без необходимости ручной авторизации пользователя через OAuth, повышая удобство использования и приватность на ТВ-устройствах.

Официальная допустимость стороннего использования интерфейса не подтверждена — решение о публикации и дальнейшем развитии остаётся за владельцем проекта.
