# VOX 6 — аудит проекта

## Методика

Инженерный аудит кодовой базы SmartTube VOX проведён в рамках старта 14-дневного спринта VOX 6 (01.10.2026 — 16.10.2026).
Аудит охватывает:
- Модульную структуру (`common`, `smarttubetv`, `MediaServiceCore`, `exoplayer-library`, `services`, `leanback`).
- Потоки данных YouTube (Innertube, VideoInfo, прямое воспроизведение, форматы DASH/URL, шифрованные подписи, SABR).
- Ядро закадрового перевода VOX (Yandex VOT, OAuth-брокер, синхронизация, Ducking, переключение аудиодорожек).
- Конвейер скачивания медиа (сегментная загрузка, Range, восстановление после сбоев, хранение, MediaStore).
- Мультиплексор Matroska/MKV (EBML, Cues, SeekHead, Duration, поддержка кодеков без транскодирования).
- Сетевой внешний запуск DIAL/SSDP.
- UI/UX Leanback для Android TV (навигация с пульта, фокус DPAD, диалоги, уведомления, локализация).
- Безопасность (хранение токенов, отсутствие PII/секретов в логах, изоляция flavor, валидация URL и манифестов).

Все находки классифицированы по уровням критичности: `CRITICAL`, `HIGH`, `MEDIUM`, `LOW`.

## Критические проблемы

### Находка 1: Утечка слушателя прогресса и повторное открытие диалога скачивания после закрытия пользователем
- **Severity**: HIGH
- **Area**: UI/UX / Lifecycle
- **File**: `common/src/main/java/com/liskovsoft/smartyoutubetv2/common/vox/download/VoxDownloadDialogHelper.kt`
- **Problem**: При показе диалога прогресса скачивания слушатель `VoxDownloadListener` регистрировался в `VoxDownloadCoordinator`, но при закрытии диалога пользователем по кнопке «Назад» или «Закрыть» слушатель не отписывался. Периодические коллбэки прогресса продолжали вызывать `showDialog()`, что приводило к мерцанию и повторному навязыванию диалога во время просмотра видео.
- **Risk**: Нарушение UX плеера, зависание интерфейса, утечка контекста Activity в слушателях.
- **Fix**: Введён флаг активности диалога `isShowing`, регистрация `onFinish` коллбэка для `AppDialogPresenter`, гарантированная отписка слушателя от координатора при закрытии диалога.
- **Status**: FIXED

### Находка 2: Риск выбора неподдерживаемого видеокодека (VP9/AV1) при скачивании
- **Severity**: HIGH
- **Area**: Скачивания / MKV / YouTube
- **File**: `common/src/main/java/com/liskovsoft/smartyoutubetv2/common/vox/download/VoxStreamResolver.kt`
- **Problem**: Метод `selectBestVideoFormat` выбирал форматы на основе разрешения без явного приоритета кодека AVC1 (H.264). В случаях, когда YouTube возвращал адаптивные потоки WebM/VP9 с более высоким битрейтом, они могли выбираться для упаковки в MKV, где парсер NALU ожидает AVC1.
- **Risk**: Ошибка мультиплексирования `UNSUPPORTED_CODEC` или сбой парсинга сэмплов при наличии доступного потока 1080p/720p в формате AVC1.
- **Fix**: Логика сортировки форматов в `VoxStreamResolver` обновлена: в первую очередь выбираются совместимые потоки AVC/H.264 в пределах выбранного разрешения, и только при их отсутствии осуществляется безопасный фоллбэк.
- **Status**: FIXED

### Находка 3: Неоптимальный выбор оригинальной аудиодорожки для сохранения в MKV
- **Severity**: HIGH
- **Area**: Скачивания / MKV
- **File**: `common/src/main/java/com/liskovsoft/smartyoutubetv2/common/vox/download/VoxStreamResolver.kt`
- **Problem**: `resolveOriginalAudio` делегировал выбор в `VotMediaFormatSelector.selectBestAudioFormat`, который исторически настроен на выбор `audio/webm` (Opus) с минимальным битрейтом для экономии трафика при загрузке в Яндекс. Для локального MKV-файла необходим поток `audio/mp4` (AAC) с полными параметрами `AudioSpecificConfig` (csd-0) и максимальным качеством.
- **Risk**: Отсутствие метаданных дорожки AAC или сбой извлечения заголовков кодека в `VoxMediaExtractorSource`.
- **Fix**: Реализован специализированный метод `selectBestMuxAudioFormat`, который выбирает оригинальный поток AAC/MP4 с максимальным битрейтом.
- **Status**: FIXED

## Высокий приоритет

### Находка 4: Отсутствие стандартизированной политики классификации сетевых ошибок и экспоненциального бэкоффа
- **Severity**: HIGH
- **Area**: Сеть / YouTube
- **File**: `common/src/main/java/com/liskovsoft/smartyoutubetv2/common/vox/download/VoxYouTubeRetryPolicy.kt`
- **Problem**: Обработка сетевых ошибок (таймауты, 403, 410, 429, 5xx, DNS) была разрознена по классам загрузчика, что затрудняло контроль за числом попыток и задержками.
- **Risk**: Бесконечные повторы при постоянных ошибках (403 без возможности обновления, 429 rate limit) либо преждевременный отказ при кратковременных задержках сети.
- **Fix**: Создан класс `VoxYouTubeRetryPolicy`, формализующий категории ошибок (`NETWORK_TIMEOUT`, `DNS_FAILURE`, `HTTP_403`, `HTTP_410`, `HTTP_429`, `HTTP_5XX`, `FATAL`) и расписание бэкоффа (1с, 2с, 4с, максимум 3 попытки). Загрузчик `VoxSegmentDownloader` переведён на эту политику.
- **Status**: FIXED

## YouTube

1. **Маршрутизация запросов**: `YouTubeMediaItemService` производит получение информации о форматах (`getFormatInfoLegacy` через `VideoInfoService`) с автоматическим переходом на `InnertubeService` при обнаружении `isUnplayable`.
2. **Защита от сбоев 403/410**: Подписанные URL потоков не сохраняются на диск. При истечении подписи загрузчик запрашивает обновление метаданных через `urlProvider`.
3. **yt-dlp как Reference**: Проведён анализ подходов yt-dlp по ротации клиентов (Android, Web, iOS, TV), резервированию форматов и обработке вызовов n-challenge. Использование сторонних бинарников, Python или FFmpeg исключено; все подходы адаптируются в нативный Kotlin/Java код.

## VOX

1. **Изоляция сессий**: Сессии перевода защищены сквозными идентификаторами `generationId` и `sessionId`. При смене видео старые сессии немедленно сбрасываются.
2. **Восстановление громкости**: Громкость оригинального видео корректно восстанавливается при завершении или паузе перевода.
3. **Синхронизация**: Плавный секундный таймер ожидания и обратный отсчёт согласованы с состоянием плеера.

## Скачивания

1. **Конечный автомат состояний**:
   `IDLE` -> `PREPARING_TRANSLATION` -> `RESOLVING_STREAMS` -> `DOWNLOADING_VIDEO` -> `DOWNLOADING_ORIGINAL_AUDIO` -> `DOWNLOADING_TRANSLATED_AUDIO` -> `READY_FOR_MUX` -> `MUXING` -> `MUXED` -> `PUBLISHING` -> `COMPLETED`.
   Терминальные состояния: `COMPLETED`, `FAILED`, `CANCELLED`.
2. **Докачка (HTTP Range)**:
   - 206 Partial Content: дописывание в конец существующего файла.
   - 200 OK: перезапись с начала.
   - 416 Range Not Satisfiable: проверка размера или перезапуск.
3. **Проверка свободного места**: Перед началом скачивания и в процессе записи проверяется наличие достаточного дискового пространства.

---

## MKV

1. **Ремультиплексирование без транскодирования**: Контейнер Matroska собирается напрямую в потоке с записью заголовков EBML, элементов SeekHead, Info, Tracks, Clusters и Cues.
2. **Длительность и таймкоды**: Корректное проставление `Duration` в элементе `Info` через прямое позиционирование (`RandomAccessFile`).
3. **Переключение дорожек**: Дорожка перевода (MP3) помечается флагом `Default=1`, оригинальная дорожка (AAC) — `Default=0`.

---

## DIAL

1. **Безопасность**: Запросы принимаются только из локальных сетей (RFC 1918 / Loopback). Внешний запуск по умолчанию отключён в настройках.
2. **Парсинг параметров**: Строгая валидация `videoId` и параметров запуска, экранирование XML в описаниях устройства `dd.xml`.
3. **Жизненный цикл**: Остановка сервера и сокетов SSDP при отключении настройки или завершении приложения.

## Производительность

- **Аллокации в горячем цикле**: В `VoxSegmentDownloader` и `VoxMatroskaMuxer` используются переиспользуемые буферы фиксированного размера (64 КБ и 256 КБ), исключая избыточную нагрузку на сборщик мусора.
- **Главный поток**: Все операции ввода-вывода (сеть, диск, MediaStore, упаковка) выполняются в фоновых пулах потоков (`Dispatchers.IO` / `Executors`).

## Диагностика и проблемы в исследовании (Live streaming)

### Находка 5: Кратковременная буферизация и падение качества стрима (Live ABR Quality Collapse)
- **Severity**: HIGH
- **Area**: Live Stream / ExoPlayer / ABR / Network
- **Symptoms**:
  - `LIVE_REBUFFER`: Кратковременный спиннер буферизации (~1 секунда) во время прямого эфира.
  - `LIVE_ABR_QUALITY_COLLAPSE`: Резкое падение адаптивного качества стрима (визуально до ~240p с ожидаемого 1080p) после прерывания.
- **Potential Areas**:
  - Опустошение буфера (buffer underrun) в живом потоке.
  - Оценка пропускной способности (Bandwidth Estimator / DefaultBandwidthMeter).
  - Алгоритм адаптивного выбора дорожки (AdaptiveTrackSelection) и агрессивное занижение битрейта.
  - Позиция живого края (live edge / target live offset).
  - Гистерезис восстановления качества после буферизации (post-rebuffer recovery / quality ramp-up).
