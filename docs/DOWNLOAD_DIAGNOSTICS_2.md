# SmartTube VOX 8 — Надежность загрузок и архитектура диагностики 2.0 (Downloads & Diagnostics 2.0)

В рамках **Patch #7** для SmartTube VOX 8 выполнена фундаментальная переработка подсистемы фоновых загрузок, классификации сбоев и телеметрии диагностики.

Данная доработка напрямую решает проблему из реального пользовательского отчёта **VOX-A-DF6567** (устройство DuneHD Pro Vision 4K / Android 11 API 30), в котором сбой завершения загрузки приводил к малоинформативному сообщению:
`"Ошибка скачивания: UNKNOWN"` со стадией `FAILED`.

---

## 1. Жизненный цикл загрузки (Download Lifecycle & Stages)

Вся цепочка загрузки теперь строго типизирована через последовательность стадий (`VoxDownloadState` / `stageName`). Любое изменение состояния сопровождается записью в диагностический лог и обновлением UI-модели:

```
[QUEUED]
   │
   ▼
[RESOLVING] (получение адаптивных видео- и аудиопотоков YouTube)
   │
   ├──────────────────────────────┐
   ▼                              ▼
[DOWNLOADING_VIDEO]    [PREPARING_TRANSLATION] (запрос к Yandex VOT)
   │                              │
   ▼                              ▼
[DOWNLOADING_AUDIO]    [DOWNLOADING_TRANSLATION] (скачивание MP3 перевода)
   │                              │
   └──────────────┬───────────────┘
                  ▼
          [READY_FOR_MUX]
                  │
                  ▼
             [PACKAGING]
                  │
                  ▼
               [MUXING] (мультиплексирование MKV с помощью VoxMatroskaMuxer)
                  │
                  ▼
             [FINALIZING] (перемещение в MediaStore / Movies / SmartTube Downloads)
                  │
                  ▼
             [COMPLETED]
```

### Дополнительные состояния:
- **`PAUSED`**: загрузка приостановлена пользователем или сохранена при выходе из приложения. Скачанные сегменты `.part` сохраняются.
- **`CANCELLED`**: загрузка отменена пользователем. Все временные сегменты и буферы немедленно удаляются.
- **`FAILED`**: произошла неустранимая ошибка. **Важно:** перед переводом задачи в статус `FAILED` предыдущая фаза обязательно сохраняется в поле `lastFailedStage`, что исключает потерю контекста сбоя (ранее стадия перезаписывалась значением `"FAILED"`).

## 2. Типизированные коды ошибок (Typed Error Codes)

Вместо общего кода `UNKNOWN` введены строго типизированные категории сбоев (`VoxDownloadErrorCode`):

| Код ошибки | Описание причины | Категория отказа |
|---|---|---|
| `STORAGE_FULL` | Недостаточно свободного места на целевом накопителе (`ENOSPC`) | `STORAGE` |
| `STORAGE_PERMISSION` | Отсутствие прав на запись в целевую директорию (`EACCES`) | `STORAGE` |
| `TEMP_FILE_FAILED` | Ошибка создания, открытия или чтения временного файла в cache | `STORAGE` |
| `OUTPUT_MOVE_FAILED` | Ошибка перемещения готового контейнера из cache в публичное хранилище | `PACKAGING` |
| `FINALIZE_FAILED` | Сбой регистрации медиафайла в MediaStore или сканирования MediaScanner | `PACKAGING` |
| `NETWORK` | Сетевой сбой соединения, обрыв сокета (`SocketException`, `SSLException`) | `NETWORK` |
| `TIMEOUT` | Таймаут соединения или чтения потока данных (`SocketTimeoutException`) | `NETWORK` |
| `RESOLVE_FAILED` | Ошибка получения потоков или дешифровки сигнатур YouTube | `NETWORK` |
| `VIDEO_DOWNLOAD_FAILED` | Сбой скачивания видеопотока | `NETWORK` |
| `AUDIO_DOWNLOAD_FAILED` | Сбой скачивания оригинальной аудиодорожки | `NETWORK` |
| `TRANSLATION_FAILED` | Ошибка генерации или скачивания аудиодорожки перевода | `TRANSLATION` |
| `UNSUPPORTED_FORMAT` | Неподдерживаемый кодек или формат потока для мультиплексора | `PACKAGING` |
| `INVALID_MEDIA` | Поврежденные медиа-данные или некорректный заголовок трека | `MEDIA` |
| `PACKAGING_FAILED` | Сбой на этапе сборки контейнера | `PACKAGING` |
| `MUX_FAILED` | Внутренняя ошибка парсинга пакетов или записи EBML-структуры | `PACKAGING` |
| `CHECKSUM_FAILED` | Несовпадение контрольной суммы или размера скачанного трека | `VALIDATION` |

## 3. Анализ корневой причины (Root Cause Extraction & Mapping)

Для безопасного извлечения первопричины из цепочки исключений Java/Kotlin реализован `VoxDownloadFailureClassifier`:

1. **Защита от циклических ссылок**: раскрутка цепочки исключений `throwable.cause` контролируется с помощью `IdentityHashMap<Throwable, Boolean>`. В случае обнаружения зацикливания или превышения глубины 15 итераций обход прерывается.
2. **Безопасная очистка (Zero-Telemetry)**: исключения очищаются от приватных пользовательских путей (`/storage/emulated/0/...`), URL-адресов с токенами авторизации и внутренних классов.
3. **Сопоставление с техническими константами**:
   - `No space left on device` / `ENOSPC` ➔ `NO_SPACE_LEFT_ON_DEVICE` (`STORAGE_FULL`)
   - `Permission denied` / `EACCES` ➔ `STORAGE_PERMISSION_DENIED` (`STORAGE_PERMISSION`)
   - `Atomic move not supported` / `EXDEV` ➔ fallback на потоковое копирование через `FileInputStream` / `FileOutputStream` с последующим удалением исходного файла.
   - `UnknownHostException` ➔ `DNS_LOOKUP_FAILED` (`NETWORK`)
   - `SocketTimeoutException` ➔ `READ_TIMEOUT` (`TIMEOUT`)
4. **Понятные сообщения для пользователя на русском языке**:
   - При нехватке места: *"Недостаточно свободного места на устройстве"*
   - При сетевых сбоях: *"Ошибка сети при загрузке. Проверьте подключение к интернету"*
   - При сбое финализации: *"Не удалось сохранить итоговый файл в папку загрузок"*
   - При сбое сборки: *"Ошибка сборки медиафайла (мультиплексирование)"*

## 4. Политика повторов (Retry Policy) и очистка (Cleanup)

- **Транзиентные ошибки**: сетевые ошибки и таймауты классифицируются как восстановимые (`isRecoverable = true`) с возможностью автоматического или ручного перезапуска задачи.
- **Фатальные ошибки**: нехватка места на диске и отказ в правах доступа классифицируются как невосстановимые без вмешательства пользователя (`isRecoverable = false`). Повторные бессмысленные запросы блокируются для экономии ресурсов и батареи.
- **Очистка временных файлов**:
   - При отмене (`CANCELLED`): удаляются все сегменты `.part` и промежуточные `.tmp` файлы данной задачи.
   - При старте сервиса: сканируется директория кэша загрузок; временные файлы сиротских задач (orphan files) старше 24 часов очищаются автоматически.
   - При успешном завершении (`COMPLETED`): временные потоки видео, оригинального звука и перевода удаляются сразу после успешного создания и финализации результирующего MKV.

## 5. Диагностика 2.0 (Diagnostics Summary & Zero-Telemetry Privacy)

Метод `VoxDownloadCoordinator.getDiagnosticsSummary()` собирает агрегированную обезличенную сводку состояния подсистемы загрузок и встраивает её в общий диагностический отчёт `VoxDiagnosticReport`:

```json
"downloadDiagnostics": {
  "activeJobsCount": 0,
  "queuedJobsCount": 0,
  "failedJobsCount": 0,
  "lastFailedStage": "FINALIZING",
  "lastErrorCategory": "STORAGE",
  "lastOperation": "MOVE_TO_MEDIASTORE",
  "safeRootCause": "NO_SPACE_LEFT_ON_DEVICE",
  "freeStorageMb": 482,
  "outputContainer": "mkv",
  "temporaryFilesCount": 0
}
```

### Защита конфиденциальности (Zero-Telemetry Privacy):
- Имена скачиваемых видео, названия каналов и ID пользователей **НЕ включаются** в диагностические отчеты.
- Полные файловые пути заменяются на стандартизированные идентификаторы хранилищ (`PUBLIC_MOVIES`, `INTERNAL_CACHE`).
- Загрузочные URL (googlevideo, yandex) с сигнатурами и токенами доступа полностью удаляются.

## 6. Разбор пользовательского инцидента VOX-A-DF6567 (DuneHD Pro Vision 4K)

### Исходные симптомы из отчёта:
1. `DOWNLOAD_FAILED`: ошибка `"Ошибка скачивания: UNKNOWN"` на этапе финализации файла.
2. `SLUGGISH_STARTUP`: задержка запуска видео до 10200 мс на 1080p 59Hz ТВ при ручной установке профиля `MAX_QUALITY` (2160p 4K).
3. `CHANNEL_FOCUS`: красные фоны карточек каналов и сбивающийся фокус при навигации DPAD вверх/вниз.

### Результаты расследования и устранения:
1. **Загрузка**:
   - В предыдущей версии общая секция `catch (Exception e)` переводила задачу в `FAILED` до вызова логгера, стирая стадию `PACKAGING`/`FINALIZING` и подменяя код ошибки на `UNKNOWN`.
   - При перемещении готового MKV через границы файловых систем на DuneHD (внутренний накопитель / внешняя флешка) системный вызов `renameTo` или `Files.move(ATOMIC_MOVE)` возвращал сбой `EXDEV`.
   - **Исправлено**: добавлен автоматический fallback на потоковое копирование при сбое атомарного переноса, а исключения теперь классифицируются с сохранением истинной стадии сбоя и безопасной причины.
2. **Автонастройка DuneHD**:
   - DuneHD Pro Vision 4K имеет аппаратный декодер 4K (HEVC/AV1/VP9), но подключен к экрану 1080p.
   - Профиль `MAX_QUALITY` выбирал поток 2160p. Если интернет-канал или буфер не справлялись, возникали множественные буферизации.
   - **Исправлено**: ручной выбор пользователя `MAX_QUALITY` остаётся неприкосновенным (не сбрасывается принудительно), однако модуль `VoxCompatibilityRiskEvaluator` при обнаружении повторных буферизаций формирует ненавязчивую рекомендацию в UI: *"Обнаружены повторные буферизации при профиле «Максимальное качество». Для более стабильной работы рекомендуется профиль «Автоматически»"*.
3. **Раздел каналов (Channel UI)**:
   - В `ChannelCardPresenter` цвет `mNewContentBackgroundColor` (темно-красный) назначался фону текстовой подложки карточки. При потере фокуса карточки оставались красными или мигали красным при пролистывании DPAD.
   - **Исправлено**: красная заливка текста полностью удалена. Добавлен аккуратный точечный индикатор 6dp (`channel_new_content_dot.xml`), отображаемый только при наличии нового контента. Подложка карточки строго следует стандартным цветам темы оформления при фокусе и потере фокуса. Добавлена сортировка каналов «По умолчанию» / «По новому контенту» / «По алфавиту».
