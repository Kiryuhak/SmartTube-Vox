# SmartTube VOX 8 — Прототип провайдера Live Translation и результаты аудита (Live Provider Prototype)

В рамках **Patch #8** выполнено исследование архитектуры провайдеров перевода прямых трансляций, реализован изолированный слой предобработки звука и стандартизирован контракт взаимодействия со шлюзом `services/vox-live-gateway`.

---

## 1. Исследованные провайдеры (Researched Providers)

1. **Yandex VOT (`api.browser.yandex.ru`)**:
   - **Ограничения**: Протокол ориентирован исключительно на законченные VOD-видео с фиксированной длительностью (`duration`). Метод `sendPartialAudio` используется только для чанковой загрузки большого файла целого видео при статусе `STATUS_AUDIO_REQUESTED`.
   - **Вердикт**: `VOD_ONLY`. Потоковый инкрементальный перевод прямых эфиров не поддерживается.
   - **Решение**: зафиксировать статус `UNSUPPORTED` без попыток симуляции и без нарезки стрима на псевдо-VOD фрагменты.

2. **Yandex Cloud SpeechKit (gRPC STT + TTS)**:
   - Поддерживает двусторонний стриминг речи, но требует сервисный аккаунт, платный биллинг Yandex Cloud и промежуточный сервер для защиты ключей.

3. **Внешние коммерческие сервисы (Whisper API, OpenAI Realtime, ElevenLabs)**:
   - Требуют индивидуальных платных API-ключей пользователей, имеют высокие сетевые задержки и строгие лимиты запросов (429).

4. **Локальный шлюз и тестовый провайдер (`services/vox-live-gateway`)**:
   - Реализована маршрутизация провайдеров (`MOCK`, `PASSTHROUGH`, `REAL_EXPERIMENTAL`, `YANDEX_VOD_ONLY`).
   - Реализован адаптер `RealExperimentalLiveTranslationProvider`, читающий настройки из серверного окружения без вшивания секретов в APK. При отсутствии ключей возвращается честный статус `UNAVAILABLE` или `AUTH_REQUIRED`.

## 2. Стандартизированные возможности и состояния (Capabilities & States)

### Состояния провайдера (`ProviderState` / `VoxLiveProviderState`):
- `AVAILABLE` — провайдер активен и готов к обработке;
- `UNAVAILABLE` — провайдер недоступен (эндпоинт отключен или не сконфигурирован);
- `UNSUPPORTED` — инкрементальный стриминг не поддерживается архитектурно (Yandex VOT);
- `AUTH_REQUIRED` — требуется валидный API-ключ или авторизация;
- `RATE_LIMITED` — превышена квота или частота запросов (HTTP 429);
- `DEGRADED` — задержка сервиса превышает допустимый порог;
- `ERROR` — внутренняя ошибка обработки.

### Возможности (`capabilities`):
- `supportsRawPcm`: `true` (для Mock, Passthrough и Real Experimental);
- `supportsEncodedAudio`: `true`;
- `supportsIncremental`: `true` (для потоковых адаптеров);
- `supportsStreaming`: `true`;
- `supportsSession`: `true`;
- `supportsCancellation`: `true`;
- `supportsSourceLanguageAuto`: `true`;
- `supportsVoiceSynthesis`: `true`;
- `supportsPartialResults`: `false`.

## 3. Предобработка аудио (Audio Preprocessing & Resampling)

Для совместимости с современными движками распознавания речи (Whisper, Vosk) реализован класс `VoxPcmAudioConverter`:
- **Формат захвата**: PCM 16-bit Little-Endian, 48 000 Гц, 2 канала (стерео);
- **Целевой формат провайдера**: PCM 16-bit Little-Endian, 16 000 Гц, 1 канал (моно);
- **Конвертация стерео в моно**: усреднение левого и правого каналов `(L + R) / 2` с защитой от переполнения short;
- **Ресемплинг 48 кГц -> 16 кГц**: детерминированная децимация 3:1 со скользящим усреднением троек сэмплов для сглаживания спектра;
- **Гарантии**: работа в памяти фиксированного размера (bounded memory), отсутствие блокировок в аудиотракте, сохранение точных временных меток PTS (`startPtsUs`, `endPtsUs`, `durationUs`), время обработки 2-секундного буфера < 1.5 мс.

## 4. Бюджет задержки (Latency Budget Breakdown)

Для достижения комфортного синхрона при переводе прямого эфира бюджет задержки распределяется следующим образом:

| Этап пайплайна | Время (мс) | Описание |
|---|---|---|
| Захват аудиофрагмента (Capture window) | 2000 | Накопление смыслового аудиофрагмента в `VoxLiveAudioFragmentAssembler` |
| Предобработка звука (Resampler 48k->16k) | 2 | Конвертация стерео 48кГц в моно 16кГц |
| Передача в шлюз (Network Upload) | 40–100 | Отправка HTTP POST на localhost / локальный шлюз |
| Потоковое распознавание речи (STT) | 800–1500 | Модель Faster-Whisper / Sherpa-ONNX |
| Машинный перевод (MT) | 200–400 | NMT с контекстным окном |
| Синтез речи (TTS) | 400–800 | Генерация аудиодорожки (Piper TTS) |
| Передача в приложение (Download result) | 40–100 | Получение готового аудио через опрос шлюза |
| Буфер синхронизации (Secondary jitter buffer) | 2500–3000 | Буфер сглаживания сетевого джиттера в `VoxLivePtsSyncController` |
| **ИТОГО задержка (End-to-End Latency)** | **~6.0–8.0 сек** | Видео задерживается на 6–8 секунд для идеального синхрона с переводом |

## 5. Защита конфиденциальности (Zero-Telemetry Privacy)

- Никакие сырые аудиоданные пользователя не сохраняются на диск сервера;
- Временные буферы чанков в памяти удаляются сразу после завершения обработки или при закрытии сессии;
- Все секреты провайдера (`VOX_REAL_PROVIDER_KEY`, `VOX_REAL_PROVIDER_URL`) хранятся исключительно в серверных переменных окружения и ни при каких условиях не передаются в APK или в диагностические логи.

## 6. Ключевые блокеры и следующий шаг (Blockers & Next Steps)

### Блокеры:
1. Общедоступные бесплатные бэкенды (включая Яндекс VOT) не поддерживают инкрементальный поток сырого аудио для прямых эфиров (`VOD_ONLY`).
2. Внешние облачные API требуют индивидуального биллинга и платных ключей, что противоречит концепции открытого и бесплатного приложения SmartTube VOX.

### Следующий шаг:
- Разработка и развертывание собственного автономного открытого микросервиса на базе **Faster-Whisper + MarianMT + Piper TTS**, адаптированного для работы в связке с `services/vox-live-gateway`.
- Экспериментальные флаги в релизе остаются строго выключенными (`VOX_LIVE_REAL_PROVIDER_EXPERIMENTAL = false`).
