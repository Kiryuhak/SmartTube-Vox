# SmartTube VOX — Авторизация Яндекс ID и сохранение токенов

## 1. Контекст проблемы

В процессе авторизации через Яндекс ID на телевизоре (Device Code Flow `ya.ru/device`):
- Пользователь вводил код подтверждения на телефоне/компьютере.
- Диалог на телевизоре получал токен и показывал «✓ Вход выполнен!».
- Однако после закрытия диалога статус оставался «Яндекс ID: Не авторизован».
- При повторных попытках вход не сохранялся, а полный сброс настроек не устранял проблему.

## 2. Причины сбоя

1. **Исключение `AndroidKeyStore` при AES-GCM шифровании**:
   В `YandexOAuthTokenStore.java` метод `encrypt()` выполнял проверку `cipher.getIV()`. В ряде реализаций `AndroidKeyStore` на Android TV вызов `cipher.init(Cipher.ENCRYPT_MODE, key, spec)` с переданным вручную `GCMParameterSpec` приводил к выбрасыванию `InvalidAlgorithmParameterException: Caller-provided IV but use of caller-provided IVs not permitted`.
   В результате шифрование возвращало `null`, а сохранение токена в `SharedPreferences` прерывалось.

2. **Отсутствие fallback-ключа на API 23+**:
   При сбое или недоступности аппаратного `AndroidKeyStore` (например, на ТВ-приставках без экрана блокировки или с кастомными прошивками) метод `getOrCreateSecretKey()` возвращал `null` вместо безопасного перехода на закрытый 256-битный ключ приложения (`vot_sec_key.bin`).

3. **Отсутствие верификации сохранения в диалоге**:
   `YandexDeviceAuthDialog` показывал статус успешного входа до проверки реального наличия токена в `VotData.hasOAuthToken()`.

4. **Несогласованность прокси**:
   `YandexBrokerClient` создавал соединения напрямую через `new URL().openConnection()`, минуя селективный VOX-прокси (`VoxHttpClientFactory`), в отличие от `YandexDeviceCodeClient`.

5. **Дублирование элементов в настройках**:
   В `PlayerSettingsPresenter` одновременно отображались несколько кнопок входа в зависимости от статуса, а диалог настроек не закрывался при переходе к экрану авторизации.

## 3. Архитектура решения

### 3.1. Безопасное AES-GCM шифрование
- **Для ключей `AndroidKeyStore`**: инициализация `Cipher.ENCRYPT_MODE` выполняется без передачи параметров (`cipher.init(Cipher.ENCRYPT_MODE, key)`), позволяя KeyStore самостоятельно сгенерировать криптографически стойкий 12-байтный IV, который затем извлекается через `cipher.getIV()`.
- **Для программных ключей (fallback / тесты)**: генерируется случайный 12-байтный IV через `SecureRandom` и передаётся в `GCMParameterSpec(128, iv)`.
- **Формат хранения**: префикс версии (1 байт) + IV (12 байт) + зашифрованный текст с тегом аутентификации GCM (16 байт) в кодировке Base64.

### 3.2. Отказоустойчивый Fallback
- Если `AndroidKeyStore` выбрасывает исключение или недоступен, хранилище автоматически переключается на 256-битный закрытый AES-ключ приложения (`vot_sec_key.bin` в защищённом каталоге приложения `context.getFilesDir()`).
- Шифрование at-rest сохраняется во всех сценариях, гарантируя отсутствие открытого хранения токенов.

### 3.3. Верификация сохранения и согласованность сети
- `YandexDeviceAuthDialog.onTokenReceived()` проверяет `mVotData.hasOAuthToken()` после записи. При сбое сохранения пользователю выводится ошибка сети/хранилища с возможностью повторной попытки.
- `YandexBrokerClient` использует `VoxHttpClientFactory.openYandexConnection(url)` для маршрутизации через VOX-прокси при его включении.

### 3.4. Очистка интерфейса настроек
- Устранены дублирующиеся кнопки. При статусе `ABSENT` отображается одна кнопка «Войти в Яндекс» со статусом «Яндекс ID: Не авторизован».
- При нажатии на кнопку диалог настроек закрывается, корректно передавая фокус на экран авторизации.

## 4. Безопасность

- Токены `access_token` и `refresh_token` никогда не сохраняются в открытом виде.
- Токены никогда не логируются в `logcat` и не передаются в строковых представлениях моделей.
- При повреждении зашифрованных данных или смене ключа хранилище безопасно сбрасывает повреждённую запись без падения приложения (fail-safe).
