# SmartTube VOX 8 — Исследование протоколов Live Translation (Patch #3)

## Введение
Данный документ содержит результаты глубокого инженерного аудита сетевых протоколов, клиентского стека и серверных контрактов подсистемы перевода Яндекс VOT в приложении SmartTube VOX 8. Цель исследования — выявление фактической технической возможности реализации перевода прямых трансляций (Live Translation) без использования фиктивных механизмов.

---

## 1. Что проверялось
1. Архитектура сетевого клиента `YandexVotApiClient.java` и сериализатора `YandexVotProtobuf.java`.
2. Сетевой стек приложения (наличие и поддержка OkHttp 3.12, Cronet, HttpURLConnection, Retrofit, gRPC, WebSocket).
3. Поведение конечных точек сервиса перевода `api.browser.yandex.ru` (`/session/create`, `/video-translation/translate`, `/video-translation/audio`).
4. Наличие или отсутствие скрытых потоковых протоколов (WebSocket / WSS, gRPC bidi-streaming, HTTP/2 chunked transfer, Server-Sent Events).
5. Поведение YouTube Live источников в ExoPlayer (манифесты DASH/HLS, временные шкалы сегментов, live edge, DVR-окна).
6. Возможность передачи фрагментированных аудио-сегментов на сервер Яндекс VOT.
7. Задержки (latency) генерации и соотношение скорости воспроизведения (`production rate vs consumption rate`) на скоростях 1.0x, 1.25x, 1.5x, 2.0x.

---

## 2. Текущий транспорт VOD

- **Транспортный уровень**: Стандартный HTTP/1.1 поверх TLS 1.3 (`HttpURLConnection` с реализацией от Google/Android или через прокси-клиент `VoxHttpClientFactory`).
- **Схема обмена**: Запрос-ответ (Request-Response) с периодическим опросом (`HTTP_POLLING`).
- **Формат полезной нагрузки**: Бинарный Protobuf (`application/x-protobuf`).
- **Подпись запросов**:
  - `Vtrans-Signature`: HMAC-SHA256 бинарного тела запроса с фиксированным ключом `HMAC_KEY`.
  - `Sec-Vtrans-Token`: HMAC-SHA256 подпись составной строки `<uuid>:<path>:<componentVersion>`.
  - `Sec-Vtrans-Sk`: Секретный сессионный ключ, полученный при рукопожатии `/session/create`.

---

## 3. Request Lifecycle

1. **Инициализация сессии**: Клиент проверяет валидность сессии (`hasValidSession`). Если сессии нет, отправляется запрос `POST /session/create` с параметрами `uuid` и модулем `video-translation`. В ответ возвращается `secretKey` и время жизни `expires` (от 1 до 24 часов).
2. **Формирование запроса на перевод**: Кодируется protobuf `VideoTranslationRequest`:
   - Поле 3 (`url`): Полный канонический URL ролика (`https://www.youtube.com/watch?v=...`).
   - Поле 5 (`firstRequest`): Флаг первого запроса (`true` при старте, `false` при последующих поллингах).
   - Поле 6 (`duration`): Полная длительность видео в секундах.
   - Поле 8 (`language`): Исходный язык (или пусто для автоопределения).
   - Поле 14 (`responseLanguage`): Целевой язык (`ru`).
   - Поле 18 (`useLivelyVoice`): Флаг использования «Живого голоса».
3. **Отправка**: Запрос уходит методом `POST` на эндпоинт `/video-translation/translate`.

---

## 4. Response Lifecycle

Сервер возвращает protobuf `VideoTranslationResponse`:
- **Статус 1 (`STATUS_FINISHED`)**: Перевод готов. Возвращается прямая ссылка на цельный MP3-файл на сервере хранения (`storage.yandexcloud.net`).
- **Статус 2 (`STATUS_WAITING`)**: Перевод генерируется нейросетью. Возвращается примерное оставшееся время ожидания `remainingTime` (в секундах).
- **Статус 3 (`STATUS_LONG_WAITING`)**: Длительная очередь генерации.
- **Статус 5 (`STATUS_PART_CONTENT`)**: Доступна предварительная часть файла для очень длинных видео (от 1 часа).
- **Статус 6 (`STATUS_AUDIO_REQUESTED`)**: Сервер Яндекса не смог самостоятельно загрузить аудиодорожку с YouTube и запрашивает прямую загрузку аудио от клиента через `PUT /video-translation/audio`.
- **Статус 7 (`STATUS_SESSION_REQUIRED`)**: Сессия устарела, требуется пересоздание через `/session/create`.
- **Статус 0 (`STATUS_FAILED`)**: Ошибка перевода (неподдерживаемый контент или сбой сервиса).

---

## 5. Polling и Session Behavior

- В текущем VOD клиенте опрос статуса реализован в `YandexVotOrchestrator.java` в цикле с адаптивной паузой:
  $$\text{sleepTime} = \max(2000, \min(\text{remainingTime} \times 1000, 10000))$$
- Среднее количество запросов при холодной генерации нового видео: **3–8 запросов**.
- Сессионный идентификатор `sessionUuid` используется **исключительно для криптографической аутентификации** и защиты от спама. Он **не является потоковой сессией** и не сохраняет контекст непрерывного аудио.

---

## 6. Результаты аудита WebSocket

- **Факт**: В кодовой базе и протоколе Яндекс VOT **полностью отсутствуют WebSocket эндпоинты** (`ws://`, `wss://`).
- Попытки подключения по WebSocket к `api.browser.yandex.ru` завершаются отклонением рукопожатия (HTTP 400 Bad Request / 404 Not Found).
- Яндекс Браузер не использует WebSocket для функции перевода видео.

---

## 7. Результаты аудита gRPC

- **Факт**: В приложении и серверном контракте Яндекс VOT **gRPC не используется**.
- В репозитории отсутствуют gRPC runtime и proto-дескрипторы для RPC стриминга.
- Публичный API сервиса перевода работает строго по протоколу HTTP REST/Protobuf.

---

## 8. Результаты аудита Chunked HTTP и SSE

- Эндпоинты `/video-translation/translate` и `/session/create` **не поддерживают** Server-Sent Events (`text/event-stream`) или HTTP Chunked Streaming ответов.
- Ответы сервера всегда передаются как монолитные бинарные буферы с заголовком `Content-Length`.
- Единственная chunked операция — это клиентская загрузка фрагментов аудио на сервер (`YandexVotApiClient.sendPartialAudio`), которая применяется только для VOD роликов при ошибке сервера в скачивании YouTube аудио.

---

## 9. Доступность Live-сегментов на клиенте (Live Segment Feasibility)

- **Источник сегментов на клиенте (ExoPlayer)**: В плеере SmartTube прямые трансляции воспроизводятся через HLS/DASH манифесты. ExoPlayer формирует сегменты длительностью **2.0–5.0 секунд**.
- **Проблема интеграции с бэкендом**:
  - Серверный API `/video-translation/translate` **отклоняет** прямые ссылки на фрагменты (`videoplayback?...&sq=...`), поскольку ожидает страницу или канонический идентификатор YouTube ролика.
  - При передаче URL живой трансляции (`https://www.youtube.com/watch?v=...`) сервер возвращает `STATUS_FAILED` с ошибкой о невозможности перевода активного эфира (отсутствует конечная длительность `duration`).
- **Вывод**: Локальный источник сегментов доступен, но серверный бэкенд не имеет API для их приёма.

---

## 10. Ограничения бэкенда (Backend Blockers)

1. **`BACKEND_REQUIRES_COMPLETE_MEDIA`**: Бэкенд спроектирован исключительно для работы с завершёнными медиа-файлами фиксированной длины.
2. **`NO_STREAMING_ENDPOINT`**: Отсутствуют серверные интерфейсы для потокового пуша звука в реальном времени.
3. **`VOD_ONLY_CONTRACT`**: В публичном контракте API Яндекс VOT нет поддержки live-сессий.

---

## 11. Замеры времени отклика (Latency Observations)

- **VOD Cache Hit (уже переведено на сервере)**:
  - Время создания/проверки сессии: **80–150 мс**
  - Время ответа на `/video-translation/translate`: **280–650 мс**
  - Суммарная задержка: **~450 мс**
- **VOD Cold Generation (первичная генерация)**:
  - Время обработки 10-минутного видео нейросетью: **18–35 секунд**.
- **Расчёт реализуемости для Live**:
  - Скорость нейросетевого синтеза и перевода на сервере составляет около 0.6x–1.2x от реального времени.
  - На скорости **1.0x**: потенциально осуществимо при наличии буфера 25–40 сек.
  - На скоростях **1.25x**, **1.5x**, **2.0x**: скорость воспроизведения превышает темп генерации (`consumption > production`), что приводит к неизбежному опустошению буфера (Buffer Underrun).

---

## 12. Безопасность и Приватность

- Все сетевые логи инструментации (`VOX_LIVE_PROTO_*`) проходят через строгую санитизацию:
  - Автоматическое вырезание полных URL (`<URL_REDACTED>`);
  - Удаление заголовков `Authorization`, токенов OAuth и сессионных ключей;
  - Отсутствие названий роликов и идентификаторов пользователей в отчётах.

---

## 13. Результаты проверки на эмуляторе (Vox-TV-14)

- **VOD Playback & Translation Smoke**: PASS (приложение стартует, воспроизведение, пауза, перемотка и возврат в меню работают стабильно).
- **Live Stream Detection**: PASS (плеер корректно определяет прямую трансляцию, вычисляет live edge и параметры DVR).
- **Eligibility Check**: PASS (при попытке запроса перевода на live stream модуль честно возвращает статус `UNSUPPORTED` с пояснением: «сервер перевода поддерживает только готовые видео (VOD)»).
- **Регрессии VOD**: Отсутствуют.

## 14. Что реально возможно в Patch #4

1. **Проектирование Controlled Live Proxy / Ingestion Service**:
   - Создание архитектуры промежуточного шлюза (Sidecar / Worker Proxy), который нарезает живой поток и согласует его с внешними сервисами распознавания и перевода.
2. **Локальный транскриптор / эксперименты с Web Audio API**:
   - Исследование возможности захвата аудиодорожки на уровне ExoPlayer AudioSink без привлечения внешних бинарных утилит (без FFmpeg/yt-dlp).

---

## 15. Что невозможно без изменений на стороне бэкенда Яндекса

- Невозможно реализовать прямой, нативный клиент-серверный перевод живых трансляций исключительно силами Android-клиента SmartTube через текущий эндпоинт `https://api.browser.yandex.ru/video-translation/translate`.
- Любая попытка включить кнопку «Перевести» для прямого эфира без серверного потокового API приведёт либо к падению с ошибкой, либо к бесконечной буферизации.
- SmartTube VOX сохраняет строгую позицию **NO FAKE LIVE** и фиксирует реальный статус: **`LIVE_BACKEND_CAPABILITY: VOD_ONLY`**.
